# Decompilation pipeline

Reference for agents matching functions in `orig/bulanci.exe`. Target
score is byte-exact COFF symbols per unit, scored by `objdiff`. Current
state lives in `report.json`; progress page is
[decomp.dev/lofcz/bulanci](https://decomp.dev/lofcz/bulanci).

Toolchain (pinned by the PE Rich Header):

| | |
|---|---|
| Compiler | MSVC 8 / VS2005 RTM (`cl 14.00.50727`) — vendored at `tools/msvc8/` |
| DirectX | DX SDK Feb 2007 — vendored at `tools/dxsdk_feb2007/` |
| Decompiler | Ghidra 12.0.x + `ghidra-delinker-extension` + `ghidra-mcp` plugin |
| Diff | `tools/objdiff-cli.exe`, ninja drives the compile, `report.json` is committed |
| Harness | `decomp-goal-harness` (run via `uv`) |

To re-verify the compiler ID:
`python scripts\internal\dump_rich_header.py orig\bulanci.exe`.

## Repo layout

```
orig/bulanci.exe        committed; SHA1 in orig/bulanci.exe.sha1
config/bulanci/         source-of-truth CSVs (mapping, units_listing)
src/bulanci/<unit>.cpp  HAND-OWNED stubs/matches; see "Source tree ownership"
include/bulanci/        HAND-OWNED headers; same lifecycle as src/
include/globals.h       shared typedefs + STUB_BODY() macro
build/                  generated .obj (gitignored)
scripts/                Python build orchestration + Ghidra MCP helpers
scripts/ghidra/         Ghidra headless Java scripts
tools/                  vendored toolchain + objdiff-cli + ninja
report.json             objdiff measures; committed, CI uploads it
```

## Source of truth

Everything downstream is rebuilt from two CSVs in `config/bulanci/`:

* **`mapping.csv`** — one row per function: `;Namespace::Name;0xstart;0xsize;__convention;varargs;return;arg...;arg...`.
  Regenerated headlessly from Ghidra via
  `scripts/ghidra/GenerateMapping.java`. The address is the stable key
  (renames don't move it).
* **`units_listing.csv`** — `unit_name,ns1,ns2,...`. Groups namespaces
  into a single translation unit. Regenerated by
  `scripts/internal/seed_units_listing.py`.

Refresh both after Ghidra changes (GUI must be closed for the lock):

```bash
python scripts/update_mapping.py "%CD%" --project bulanci ^
    --program bulanci.exe --output config\bulanci\mapping.csv
python scripts/internal/seed_units_listing.py
```

Unnamespaced functions are promoted to `_Globals::FUN_xxx` so the
generator always has a C++ namespace to bind to.

## Source tree ownership (splat-style)

**`src/bulanci/<unit>.cpp` and `include/bulanci/<unit>.h` are
hand-owned once they exist.** The pipeline never bulk-overwrites them.
This is the same contract `splat` / sotn-decomp / pokeemerald enforce
between their hand-owned `src/` and auto-regenerated `asm/` trees.

Every function block is wrapped in address-keyed markers:

```cpp
// src/bulanci/ODSImage.cpp
#include "ODSImage.h"

// !FUNC 0x00418c00 BEGIN
/* 418C00-418C5A 0005A */
void* ODSImage::FUN_00418c00(int* param_1) { STUB_BODY(); return 0; }
// !FUNC 0x00418c00 END
```

```cpp
// include/bulanci/ODSImage.h
class ODSImage {
public:
    // !DECL 0x00418c00 BEGIN
    /* 418C00 */ void* FUN_00418c00(int* param_1);
    // !DECL 0x00418c00 END
};
```

`STUB_BODY()` is the no-op marker (defined in `include/globals.h`)
that tells `sync_units.py` "this block is not yet matched". Once you
replace `STUB_BODY()` with a real body, `sync_units` treats the block
as matched: it's preserved verbatim on every subsequent run and
migrated whole if Ghidra reassigns the function to a different unit.

### When to run what

| Situation | Command |
|---|---|
| First time, or fresh clone | `python scripts/configure.py` |
| `mapping.csv` / `units_listing.csv` changed | `python scripts/sync_units.py` |
| You just hand-edited a stub body to match | nothing — `sync_units` will preserve it on next run |
| Nuke and re-scaffold from scratch (destructive) | `python scripts/generate_sources.py --force` |
| New unit appeared in `units_listing.csv` | `python scripts/generate_sources.py` (scaffolds only missing units) |
| Refresh `build/orig/*.obj` after Ghidra changes | `python scripts/configure.py` |
| Recompile and refresh `report.json` | `tools\ninja\ninja.exe && progress_update.bat` |

`sync_units.py` is idempotent; a second run does nothing.

### Cross-unit migration of matched code

When Ghidra reassigns a *matched* function (e.g., `ODSImage::Foo` →
`CDSImage::Foo`), `sync_units` migrates the block verbatim — including
its signature line, which still says `void ODSImage::Foo(...)`. You'll
get a compile error pointing at the moved block; fix the namespace
prefix by hand. This is intentional: auto-rewriting hand-written
signatures would silently corrupt matched code if a parameter type
also shifted.

## Workflow: match one function

1. Pick a candidate. Either:
   * `python scripts/pick_unit.py` — selects the highest-leverage unit
     from `report.json` (good if you'll work the whole unit).
   * `python scripts/internal/near_miss.py --print LENGTH` — lists
     paired symbols where the bytes are *close* but not equal. Easiest
     wins are in the `EXACT` (already match), `CLOSE`, and `LENGTH`
     buckets in that order.
2. Inspect both sides:
   ```bash
   tools\objdiff-cli.exe diff --project . --unit <unit> ^
                              --output - --format json-pretty "<name>"
   ```
   Or run `uv run decomp-goal run --repo "%CD%" --unit <unit>` for the
   harness loop.
3. **Fix the Ghidra signature first.** Ghidra's auto-inferred prototype
   is usually wrong on tiny functions: it under-counts stack args
   (treats methods as `__stdcall(arg)` instead of `__thiscall(this)`),
   mistypes returns (`uchar` where `cdq` says `__int64`), and so on.
   Set the right prototype via MCP `set_function_prototype` or in the
   Ghidra GUI, then `save_program`. Update the matching row in
   `config/bulanci/mapping.csv` by hand (the next
   `promote_namespaces` run will re-export from Ghidra so the manual
   edit is just a shortcut).
4. `python scripts/sync_units.py` to regenerate the stub with the new
   signature.
5. Replace the `STUB_BODY()` line in `src/bulanci/<unit>.cpp` with a
   real C++ body. Use the `bulanci.exe.c` Ghidra export (File → Export
   Program → C/C++) as the starting point — it already reflects
   `set_function_prototype` results.
6. Compile + score:
   ```bash
   tools\ninja\ninja.exe
   progress_update.bat
   ```
7. `report.json` updates; CI picks it up.

Do not edit blocks outside the `// !FUNC` / `// !DECL` markers. The
prelude and class skeletons are regenerated whenever `sync_units` has
to rewrite the file.

### Why our compiled .obj symbols pair with ExportDelinker's

`cl.exe` emits MSVC mangled names like
`?FUN_00467430@CDSApp@@QAEXXZ`, while `ExportDelinker.java` writes the
demangled qualified form (`CDSApp::FUN_00467430`) into the target
object. `objdiff-cli report generate` pairs symbols by exact raw-name
equality, *not* by demangling (encounter/objdiff#279), so without
intervention nothing ever pairs.

`scripts/internal/compile_unit.py` is the ninja wrapper that runs
`cl /c` and then `scripts/internal/demangle_obj_symbols.py`, which
rewrites every `?...@...@...` symbol in the produced `.obj` down to
the same qualified form via the Win32 `UnDecorateSymbolName` API
(`UNDNAME_NAME_ONLY`). It's idempotent — symbols that don't start
with `?` are left alone. After this both sides of the diff use
identical raw names and pairing works the way report.json expects.

The same rewriter also strips MSVC's leading-underscore prefix from
C-linkage data symbols whose stripped form matches one of Ghidra's
auto-naming patterns (`DAT_xxxxxxxx`, `LAB_xxxxxxxx`,
`PTR_<api>_xxxxxxxx`, `s_xxx_xxxxxxxx`, `switchD_*`,
`switchdataD_*`, `IMAGE_DOS_HEADER_*`, `thunk_FUN_*`).  This lets
our compiled `mov eax, offset _DAT_xxxx; ret` align with
ExportDelinker's relocation against the bare `DAT_xxxx` symbol.

### Externs for ExportDelinker's data symbols

ExportDelinker preserves the original `.text` bytes verbatim and emits
COFF relocations against the data symbols the function touches
(`DAT_xxxxxxxx`, `PTR_<api>_xxxxxxxx`, `LAB_xxxxxxxx`, ...).  For our
compiled stub to produce a matching relocation it needs to *see* the
same symbol name.  `scripts/internal/extract_externs.py` walks every
`build/orig/bulanci/*.obj`, collects symbol-table entries that are
referenced but never defined in our set, filters them to the
Ghidra-style naming patterns above, and writes them into
`include/bulanci/_externs.h` as `extern "C" unsigned char NAME;`.
That header is included from `include/globals.h` so every translation
unit sees the declarations.

Refresh it after `configure.py` rebuilds the target objects:

```bash
python scripts/internal/extract_externs.py
```

The type is intentionally `unsigned char` — only the *symbol name* and
the *relocation type* (DIR32) matter for pairing.  Hand-matched bodies
cast the address as needed: `return reinterpret_cast<T*>(&DAT_xxxx);`.

### Auto-matching simple patterns

`scripts/internal/match_global_returns.py` is the first
pattern-matcher: it picks every size-6 pointer-return method, asks
Ghidra MCP for the decompilation in 15-function batches (the MCP
endpoint silently caps batches at 20), and when the body parses as
`return &DAT_xxxxxxxx;` it rewrites the matching `// !FUNC <addr>`
block in `src/bulanci/<unit>.cpp` with the real return expression.
Sync is preserved by `sync_units.py` because the rewritten body no
longer contains `STUB_BODY(`.

Add more matchers in the same shape for other patterns (member-field
getters, vftable writes, this-adjusting thunks, MSVC EH funclets) as
they become the largest remaining buckets in
`scripts/internal/near_miss.py`.

## Workflow: refresh from Ghidra changes

After renaming/promoting/annotating in the Ghidra GUI:

1. Save in Ghidra (`Ctrl+S`), then close the GUI (lock must be free).
2. `python scripts/configure.py` does the whole chain:
   * runs Ghidra headless (`ExportDelinker` → `build/orig/*.obj`)
   * scaffolds any new units (`generate_sources.py`)
   * migrates blocks in existing units (`sync_units.py`)
   * regenerates `build.ninja` and `objdiff.json`
3. `tools\ninja\ninja.exe && progress_update.bat`.

`configure.py --ghidra-mode tempdir` forces a fresh import +
auto-analysis into a throwaway project (works even with the GUI open;
~1.5 min on `bulanci.exe`). `--skip-ghidra` skips the COFF refresh and
only updates sources/ninja/objdiff.

## Automated namespace promotion

Before the source tree is useful, run the ten-pass chain that
mechanically attributes functions to classes. Close Ghidra first.

```bash
python scripts/promote_namespaces.py
```

The passes, in order (see the script for `--skip-*` flags and tuning
knobs):

1. **`ApplyFidDb.java`** — applies single-match FunctionID hits to
   default-named functions. Names CRT helpers Ghidra's RTTI pass
   misses. Requires `setup_fiddb.py` to have run once.
2. **`AssignEntryPoints.java`** — tags PE entry, follows
   `RegisterClass*` / `DialogBox*` arg slots to anchor `WinMain`,
   `WndProc`, `DialogProc`.
3. **`PromoteMsvcrt.java`** — moves underscore-prefixed MSVC CRT
   helpers (`_malloc`, `__SEH_prolog4`, `___tmainCRTStartup`, …) into
   `Runtime::MSVCRT`.
4. **`PromoteVftableMembers.java`** — reparents every RTTI vftable
   member into its class namespace.
5. **`PromoteByVtableWrite.java`** — finds `STORE` ops writing a known
   vftable into `*this`; whoever does that is a ctor/dtor of that
   class.
6. **`AssignByStringRefs.java`** — function refs to a defined string
   matching exactly one class name → reparent.
7. **`AssignByThisPointerType.java`** — stored first-param type is
   `Class*` → reparent.
8. **`PromoteByConstantThis.java`** — aggregates per-callee the type
   the decompiler infers for arg0 across call sites; dominant
   `Class*` wins.
9. **`PropagateCallerNamespaces.java`** — fixed-point: function whose
   entire caller set is in one class becomes a member of that class.
10. **`PromoteEhFunclets.java`** — `Catch@xxxx` / `Unwind@xxxx`
    inherit the namespace of the nearest non-funclet function within
    0x40 bytes preceding (runs last so prior assignments inform it).

`GenerateMapping.java` runs at the end and re-exports `mapping.csv`.
Tuning examples:

```bash
python scripts/promote_namespaces.py --skip-eh-funclets
python scripts/promote_namespaces.py --callgraph-ambiguity 1
python scripts/promote_namespaces.py --constant-this-min-sites 1 \
                                     --constant-this-dominance 0.66
```

## One-time setup

### SDK type archives (DirectX + Win32 .gdt)

Two pre-built archives ship with the repo:

* `tools/dxsdk_feb2007/gdt/directx_feb2007.gdt` — DDraw / DSound / DInput COM vtables.
* `tools/msvc8/gdt/win32_msvc8.gdt` — Win32 API surface (`windows.h`, `objbase.h`, `mmsystem.h`).

Apply once (Ghidra closed):

```bash
python scripts\apply_gdt.py --mode existing
```

After this, decompiled DirectX calls render as
`pDS->lpVtbl->CreateSoundBuffer(...)` and Win32 args use real types
(`STARTUPINFOA`, `OVERLAPPED`, `WIN32_FIND_DATAA`, …). Rebuild the
archives with `python scripts\build_gdt.py` (see script `--help`).

### FidDb

```bash
git clone https://github.com/NationalSecurityAgency/ghidra-data ../ghidra-data
$env:GHIDRA_DATA = "$(Resolve-Path ..\ghidra-data)"
python scripts\setup_fiddb.py
```

`vsOlder_x86.fidb` covers VS2005 RTM. Runs against a throwaway project
so the real `bulanci.gpr` can stay open.

## decomp-goal-harness

Per-unit iteration loop for AI agents:

```bash
uv run decomp-goal run --repo "%CD%" --unit _Globals
```

The harness reads `decomp-goal.toml`, which calls `scripts/oracle.py`:

* `--build` reruns `objdiff-cli` and refreshes `report.json`.
* `--score --unit U` extracts the unit's measures into the harness's
  `{matched, score, exact_bytes, total_bytes, matching_prefix_bytes,
  matching_prefix_percent, first_mismatch_offset}` schema.
* `--diff --unit U` shells out to `objdiff-cli diff` for a text dump.

Annotation agents (rename / type Ghidra symbols) use the MCP plugin on
`http://localhost:8089`; class-level claims serialise through
`scripts/agent_coord.py` (see `docs/ROADMAP.md` for the scaling plan).
