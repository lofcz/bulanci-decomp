# BitmapSprite (ClassID 52) — engine-side reference

The `BitmapSprite` name is the unpacker's convention; the editor source
has no entry for ClassID 52. The format is game-side only.

This file is the **ASM-matching reference** for ClassID 52 plus its FLX
animation payload: function table, struct layouts, opcode dispatch,
algorithms, and the runtime transparency model. The on-disk byte layout
of the FLX frame stream is documented in
[`flx_file_format.md`](flx_file_format.md); both files describe the
same bytes from two layers (container ↔ FLX stream).

---

## 1. Function reference

All addresses are stable RVAs in `orig/bulanci.exe`.

### 1.1 Factories & registration

| Address    | Symbol                 | Role                                                    |
|-----------:|------------------------|---------------------------------------------------------|
| `0x0047cdd0` | (init stub)           | Registers ClassID 52 with `CDSResInfo` (`0x004b7e08`). Pushes factory `0x00432a50` and ClassID `0x34`. |

### 1.3 Render-side (CPoemScroller + blit kernels)

| Address    | Symbol                          | Role                                                          |
|-----------:|---------------------------------|---------------------------------------------------------------|
| `0x004368d0` | `CPoemScroller::BlitDispatch` | Master blit dispatcher. Picks a kernel from one of 5 tables (§4). |
| `0x0043f470` | `BlitChromaKey`               | Source-chroma-key blit (`if (src != key) dst = src`).         |
| `0x004414e0` | `BlitMasked`                  | Mask-plane blit (per-pixel alpha from `consumer+0x20`).       |
| `0x004360d0` | `GetPaletteBuffer`            | Returns palette base when `consumer+0x34` is in `[1, 256]`, else 0. |
| `0x004360f0` | `GetColorPlane`               | Returns `consumer+0x1c` adjusted by `consumer+0x34 * 4` bytes (the color plane base; consumer+0x34 is a sub-slot offset). |

### 1.4 Blit-kernel dispatch tables (data)

5 parallel function-pointer tables, all indexed by `(src_format << 3) | dst_format` (row stride = 8 entries × 4 bytes = 32 bytes; valid rows = the supported pixel-format pairs). Each entry is a fully specialised blit kernel for that source/destination pixel-format combination.

| Address     | Symbol                  | Selected when                                                              |
|------------:|-------------------------|----------------------------------------------------------------------------|
| `0x004b08c8` | `BlitTable_Opaque`     | `consumer+0x14 == 0xFFFFFFFF` AND `consumer+0x18 == 0xFF` AND `consumer+0x20 == NULL` |
| `0x004b09c8` | `BlitTable_DestKey`    | `consumer+0x14 != 0xFFFFFFFF` (destination chroma override)               |
| `0x004b0ac8` | `BlitTable_ChromaKey`  | `consumer+0x18 != 0xFF` AND `consumer+0x20 == NULL` (source chroma only)  |
| `0x004b0bc8` | `BlitTable_Masked`     | `consumer+0x20 != NULL` AND `consumer+0x18 == 0xFF` (mask only)           |
| `0x004b0cc8` | `BlitTable_KeyAndMask` | `consumer+0x20 != NULL` AND `consumer+0x18 != 0xFF` (chroma + mask)       |

Only `BlitDispatch @ 0x004368d0` references these.

## 2. Struct layouts

### 2.1 ClassID-52 handle (size 0x50)

| Offset | Type    | Field                              |
|-------:|---------|------------------------------------|
| `+0x00` | vtable* | primary (`CDSObject`)              |
| `+0x04` | vtable* | secondary subobject                |
| `+0x08` | `void*` | source stream (set by `Read`)      |
| `+0x0c` | `void*` | parent `CBulanci`                  |
| `+0x1c` | vtable* | tertiary                           |
| `+0x20` | `u32`   | refcount                           |
| `+0x24` | vtable* | per-instance ID                    |
| `+0x28` | vtable* | type-tag (embedded `CDSChain` head)|
| `+0x2c..+0x4f` | bytes | reserved / runtime scratch    |

Doesn't hold pixel data — it's a lazy wrapper. Pixels live in a
sibling `CBulPicture` bound at first draw.

### 2.2 `CBulPicture` (size 0x470 = 1136 bytes)

| Offset | Type                | Field                                                         |
|-------:|---------------------|---------------------------------------------------------------|
| `+0x00` | vtable*            | (4 vtables at `+0x00 / +0x04 / +0x10 / +0x18`)                |
| `+0x68` | `CDSBitmap*`       | Decoded surface (init `0`)                                    |
| `+0x6c..+0x46b` | `u32[256]` | RGBA palette, BGRA in memory; init `0xFFFFFFFF`           |
| `+0x46c` | `u8`              | (tail byte)                                                   |
| `+0x46d` | `u8`              | Transparent palette index (`0xFF` = no key; init by `CBulanci::FUN_004101d0` at `+0x004102a6`) |

`CBulPicture::DrawSurface @ 0x0040b050` reads `+0x46d`; when not
`0xFF` it sets `flags = 0xC` (= `8 | 4`, i.e. "chroma-key active") and
`color_key = N * 0x010101`, otherwise `flags = 8`. Then calls
`BlitDispatch(scroller, this+0x30, this+0x68, NULL, &flags)`.

### 2.3 FLX "consumer" object (the `param_2` of `DecodeFrame`)

The pointer passed to `DecodeFrame` is a consumer/surface object —
**not** the `CBulPicture`. Its layout (as observed by the chunk handlers
and `BlitDispatch`):

| Offset | Type    | Field                                                                                  |
|-------:|---------|----------------------------------------------------------------------------------------|
| `+0x04` | `u32`  | observer move target (slot index for `NotifyMove`)                                     |
| `+0x08` | `u32`  | width (read by `NotifyDirtyAll`)                                                       |
| `+0x0c` | `u32`  | pixel-format code (used as row index into blit dispatch tables)                        |
| `+0x10` | `u32`  | stride / pitch (passed to blit kernels)                                                |
| `+0x14` | `u32`  | destination chroma key (init `0xFFFFFFFF` = no key)                                    |
| `+0x18` | `u8`   | **source chroma index** (set by FLX opcode `0x0D`)                                     |
| `+0x1c` | `u8*`  | color plane base pointer (the 8-bit pixel buffer)                                      |
| `+0x20` | `u8*`  | **mask plane** base pointer (NULL until first `0x0E`/`0x0F`; allocated by `AllocMaskPlane`) |
| `+0x24` | `u32`  | clip rect base (passed to per-blit rect-intersect)                                     |
| `+0x34` | `i32`  | sub-slot offset (passed through `GetColorPlane` / `GetPaletteBuffer`)                  |
| `+0x38` | `void**`| observer array base                                                                   |
| `+0x40` | `u32`  | observer count                                                                         |

## 3. `DecodeFrame` state machine

```text
void CDSFlxFile::DecodeFrame(this, u32 *cursor, void *consumer)
    cursor_in   = *cursor                          ; capture for circular-buffer test
    frame_base  = body_base + *cursor              ; in-mem path (this+0x34 == NULL)
    frame_size  = u32 @ frame_base                 ; bytes incl. 5-byte header
    n_inner     = u8  @ frame_base + 4             ; inner-chunk count
    any_pixel   = false                            ; set when an opcode wrote to color/mask
    chunk_pos   = frame_base + 5
    for i in 0..n_inner-1:
        size  = u32 @ chunk_pos                    ; chunk total bytes incl. header
        tag   = u8  @ chunk_pos + 4
        body  = chunk_pos + 5
        n     = size - 5
        switch tag:                                ; see §3.1
            0  : DecodeRleColor(n, body, GetColorPlane(consumer));      any_pixel = true
            4  : DecodeDeltaColor(n, body, GetColorPlane(consumer));    any_pixel = true
            8  : DecodeCopyColor(n, body, GetColorPlane(consumer));     any_pixel = true
            9  : DecodePaletteRgb(n, body, GetPaletteBuffer(consumer)); any_pixel = true
            10 : { i16 x = body[0..1]; i16 y = body[2..3]; NotifyMove(consumer, &x); }
            11 : DecodeRegionList(n, body, consumer)
            12 : { u16 ticks = body[0..1]; NotifyFrameTime(consumer, ticks); }
            13 : { *(u8*)(consumer+0x18) = body[0]; any_pixel = true; }
            14 : if (*(consumer+0x20) == 0) AllocMaskPlane(consumer);
                 DecodeRleColor(n, body, *(u8**)(consumer+0x20));       any_pixel = true
            15 : DecodeDeltaColor(n, body, *(u8**)(consumer+0x20));     any_pixel = true
        chunk_pos += size
    if any_pixel: NotifyDirtyAll(consumer)         ; broadcast (0,0,w,h)
    if (cursor_in == *cursor):                     ; nobody advanced — we did it
        *cursor += frame_size
        if (*cursor >= this+0x40): *cursor = this+0x3c   ; circular wrap (ring loop)
```

Observed inner-opcode histogram across the 130-sprite master pack
(1305 frames total):
`{0x00:538, 0x04:1581, 0x09:311, 0x0a:315, 0x0b:107, 0x0c:58, 0x0d:6, 0x0e:230, 0x0f:315}`.

### 3.1 Opcode summary

| Tag  | Symbol               | Target                  | Source ref           |
|-----:|----------------------|-------------------------|----------------------|
| `0x00` | `DecodeRleColor`   | color plane (`+0x1c`)   | FLI BRUN (id 15) shape; tag renumbered |
| `0x04` | `DecodeDeltaColor` | color plane             | FLI LC (id 12) shape; tag renumbered |
| `0x08` | `DecodeCopyColor`  | color plane             | `memcpy` (FLI COPY shape) |
| `0x09` | `DecodePaletteRgb` | palette buffer          | **FLI COLOR_256 (id 4) shape, renumbered** |
| `0x0A` | (inline)           | `NotifyMove`            | sub-image position broadcast |

| `0x0C` | (inline)           | `NotifyFrameTime`       | `u16` frame duration |
| `0x0D` | (inline)           | `consumer+0x18` (u8)    | source chroma key |
| `0x0E` | `DecodeRleColor`   | mask plane (`+0x20`)    | (alloc on demand) |
| `0x0F` | `DecodeDeltaColor` | mask plane              | |

## 4. Decoder algorithms (pseudocode mirrors of Ghidra)

### 4.1 `DecodeRleColor` @ `0x00432740`

```text
while src < end:
    N = i8(read u8)
    if N == 0:        count = u16(read); v = u8(read); emit (count + 1) * [v]
    elif 1 <= N <= 127: v = u8(read);                  emit (N + 1) * [v]
    else:             copy (256 - N) literal bytes verbatim
```

The `N == 0` long-run escape is a Bulanci extension over stock FLI BRUN.

### 4.2 `DecodeDeltaColor` @ `0x00432780`

```text
while src < end:
    S = u8(read)
    if S == 0xFF: skip = u16(read)
    else        : skip = S
    dst += skip
    N = i8(read u8)
    if N == 0:        continue                                ; no-op separator
    elif N == 0x80:   c = i16(read)
                      if c >= 0: emit (c + 1) * [u8(read)]
                      else     : copy (-c) literal bytes
    elif 1 <= N <= 127: emit (N + 1) * [u8(read)]
    else:             copy (256 - N) literal bytes
```

### 4.3 `DecodeCopyColor` @ `0x004327e0`

```text
memcpy(dst, src, n)
```

### 4.4 `DecodePaletteRgb` @ `0x00432800`

**Single cursor walks the 256-entry BGRA palette across the chunk.**
The first byte of each packet is a *relative* skip (FLI/FLC
`COLOR_256` semantics — NOT an absolute start index):

```text
cursor = 0
while src < end:
    skip  = u8(read)            ; cursor += skip
    count = u8(read) + 1        ; write `count` BGRA entries
    cursor += skip
    repeat count:
        palette[cursor].B = u8(read)
        palette[cursor].G = u8(read)
        palette[cursor].R = u8(read)
        ; alpha byte left untouched at whatever buffer init wrote
        cursor += 1
```

Ghidra-level (`param_3` is `u16*`; `+ skip * 2` advances by `skip * 4`
bytes = `skip` BGRA slots):

```c
param_3 = param_3 + (uint)*param_2 * 2;          // cursor += skip
param_2 = param_2 + 2;
iVar2  = *pbVar1 + 1;                             // count = body[1] + 1
do {
    *param_3                  = *(u16*)param_2;   // dst[0..1] = src[0..1]
    *(u8*)(param_3 + 1)       = param_2[2];       // dst[2]    = src[2]
    param_2 = param_2 + 3;
    param_3 = param_3 + 2;                         // cursor += 1 BGRA slot
} while (--iVar2 != 0);
```

89/130 master-pack sprites carry an inline palette; the remaining 41
inherit a palette from a sibling resource at runtime via the engine's
ambient render context. The inheritance rule is empirically
**"most-recently-loaded inline-palette sibling, in resource load
order"** — every recolour variant in the master pack is a contiguous
ID-range follower of an inline-palette head sprite (see §9 for the
groupings). The unpacker mirrors that rule by carrying a single
1024-byte palette buffer across the per-pack `save_resource` loop in
`tools/bulanci_unpack/bulanci_unpack.py`; sprites without an
opcode-0x09 packet seed their decode from the previous sibling's
final palette and surface the link in `decoded.inheritedFrom` /
`decoded.paletteSource == "inherited"`. All 41 master-pack recolour
variants now render in their authentic colours.

### 4.5 `DecodeRegionList` @ `0x00432850`

Buffers `(u8 kind, i16 x, i16 y)` records on the stack (max 32) until
end of chunk, then fans them out via `NotifyRegionList @ 0x00436eb0`.
No count prefix — the chunk size bounds the loop.

## 5. Runtime transparency model

`BlitDispatch @ 0x004368d0` is the single point where the engine picks
its blit kernel. The decision tree (for `param_4 == NULL`, i.e. the
default `CBulPicture::Draw` path):

```text
if consumer+0x14 == 0xFFFFFFFF:                       ; no dest override
    if consumer+0x18 == 0xFF:                         ; no source chroma
        if consumer+0x20 == NULL:  BlitTable_Opaque   ; ←─ 88/130 sprites
        else:                       BlitTable_Masked  ; ←─ 39/130 sprites
    else:                                             ; source chroma set
        if consumer+0x20 == NULL:  BlitTable_ChromaKey ; ←─ 3/130 sprites
        else:                       BlitTable_KeyAndMask
else:
    BlitTable_DestKey                                 ; not seen in master pack
```

**Only two `consumer+0x??` slots are reachable from the FLX stream:**
* `+0x18` (source chroma) — written by opcode `0x0D` (3 sprites).
* `+0x20` (mask plane) — lazily allocated by opcodes `0x0E`/`0x0F`
  (39 sprites).

`+0x14` (destination chroma) is **never** touched by an FLX opcode and
is initialised to the DDraw `NO_COLORKEY` sentinel `0xFFFFFFFF`. The
remaining 88 sprites therefore hit the **opaque blit** at the
per-sprite layer. Their in-game cut-out comes from the destination
back-buffer's own chroma key (typical DDraw 8bpp pattern; the
back-buffer's create-flags carry the screen chroma, and the
buffer-to-screen flip honours it). That layer lives upstream of
`CDSFlxFile` and is not pinned to a specific function yet.

## 6. Container header (0x2c bytes)

Eleven little-endian u32s. The 5-byte frame-0 header *overlaps* file
offsets `0x24..0x28`: `encodedSize3` doubles as frame-0 `frameSize`,
and the low byte of `packed` is frame-0 `numInner`.

| Off | u32           | Empirical meaning (130/130 samples)                                       |
|----:|---------------|---------------------------------------------------------------------------|
| `+0x00` | `totalSize`     | `== len(raw)` = `.eap` record size                                    |
| `+0x04` | `encodedSize`   | = frame-0 `frameSize`                                                 |
| `+0x08` | `encodedSize2`  | Usually `== encodedSize`; multi-stream divergence on 44/130 sprites   |
| `+0x0c` | `width` (legacy)| Display-tile width hint? Commonly `104`; sentinels `0` (compound) and `0xFFFFFFFF` (fit). NOT the bitmap width. |
| `+0x10` | `height` (legacy)| **Actual BITMAP WIDTH in pixels.** Mis-labeled historically.         |
| `+0x14` | `frameCount`     | **Actual BITMAP HEIGHT in pixels.** Mis-labeled historically.        |
| `+0x18` | `channels`       | Always `3` (BGR palette triplets)                                    |
| `+0x1c` | `inMemSize`      | Runtime alloc hint; commonly `0x470` = `sizeof(CBulPicture)`         |
| `+0x20` | `flags`          | `== frameCount - 1` = animation length minus one (130/130)           |
| `+0x24` | `encodedSize3`   | `== encodedSize`; **doubles as frame-0 `frameSize`**                  |
| `+0x28` | `packed`         | `low byte = frame-0 numInner`; high 3 bytes = first 3 body bytes      |

The `width` / `height` field name swap is confirmed two ways:

1. **Decode-size invariant.** Every opcode-0x00 (RLE keyframe) chunk
   decompresses to exactly `fields[4] * fields[5]` bytes on all 538
   keyframe chunks in the pack.
2. **Visual orientation.** Rendering as `fields[4]` wide × `fields[5]`
   tall produces recognisable sprites; the transpose rotates everything
   90°.

The manifest preserves the legacy field names but spells out the real
geometry as `bitmapWidth` / `bitmapHeight` under `decoded`.

## 7. Frame-stream layout

Conceptually, after the 0x2c-byte header the rest of the file is a
chain of back-to-back animation frames. Because the first 5-byte frame
header overlaps the file header (`encodedSize3` + low byte of `packed`),
the layout is:

```
+0x00 .. +0x23   eleven u32 file-header fields (totalSize..flags)
+0x24 .. +0x27   u32 frameSize (== encodedSize3)
+0x28            u8  numInner  (low byte of `packed`)
+0x29 ..         body of frame 0 (numInner inner chunks back-to-back)
                 ... frame 1, frame 2, ... each prefixed by
                 the same 5-byte (u32 frameSize, u8 numInner) header ...
EOF              reached exactly after the last frame's body
```

The chain terminates exactly at EOF on all 130/130 samples and
`flags + 1 == frameCount` is preserved everywhere.

`numInner` histogram across all 1305 frames:

| `numInner` | frames | meaning                                                |
|-----------:|-------:|--------------------------------------------------------|
|   0        |   449  | empty frame — "reuse previous bitmap" hint             |
|   1        |  1365  | single-chunk frame (most common)                       |
|   2        |   624  | pixels + palette, etc.                                 |
|   3        |   194  | three-chunk frame                                       |
|   4        |    49  | rare                                                    |
|   5        |    14  | rare                                                    |

Empty frames are always exactly 5 bytes long.

### 7.1 Ring frame (FLI/FLC loop convention)

`DecodeFrame`'s closing branch advances the cursor by `frameSize` and,
when it reaches `*(this + 0x40)` (stream end), wraps to
`*(this + 0x3c)` (stream start). This is the FLI/FLC ring-buffer idiom.

**Empirical: 130/130 master-pack sprites satisfy
`snapshots[-1] == snapshots[0]` at the pixel level.** Two structural
variants appear:

* **Explicit re-keyframe** (68/130): the last frame carries a full
  keyframe (opcodes `[0, 14]` = RLE-color + RLE-mask, or `[0, 9]` =
  RLE-color + palette, etc.) that rewrites the bitmap to frame 0's
  content.
* **Empty ring** (62/130): last frame has `numInner == 0`; the bitmap
  is already on its loop point from the previous frame.

## 8. Unpacker output

For every BitmapSprite, the unpacker writes (next to the raw payload
`res_*_52_BitmapSprite.bin`):

* `res_*_52_BitmapSprite.atlas.png` — horizontally-stacked RGBA atlas
  (one stripe per frame, ring frame dropped).
* `res_*_52_BitmapSprite.atlas.json` — sidecar with `frameWidth`,
  `frameHeight`, `frameCount`, `framesStored`, `paletteSource`,
  `transparencySource`, `maskPlanePresent`, a per-frame `frames[]`
  array (engine opcodes applied, optional `move` / `duration` /
  `hasRegions` / `setTransparent`), and `ringFrameIndex` / `ringFrame`
  when applicable.
* `res_*_52_BitmapSprite.atlas.gif` — looping GIF89a preview
  (per-frame local color tables for palette-cycle sprites; chroma
  slot marked transparent via GCE; infinite-loop Netscape extension).

`transparencySource` reflects which engine path the sprite would have
hit, with one synthetic case for the 88 implicit-opaque sprites:

| Value         | Count | Method                                                                                  |
|---------------|------:|-----------------------------------------------------------------------------------------|
| `mask-plane`  | 39    | Engine-authoritative. `(color, mask) == (corner_color, corner_mask)` → transparent.     |
| `explicit`    |  3    | FLX opcode `0x0D` set `N`; remap palette entries sharing `palette[N]`'s RGB to alpha 0. |
| `perimeter`   | 86    | Synthetic chroma key — perimeter-pixel RGB tally, dominant RGB (>50% of perimeter) becomes the key. Matches the in-game destination chroma-key effect. |
| `none`        |  2    | Perimeter has no dominant RGB across frames — content fills the bitmap. Leave opaque.   |

The chroma-key and mask-plane paths reserve an unused palette slot
per sprite and remap transparent pixels to that slot (PNG `tRNS` /
GIF GCE transparent index).

## 9. Open questions

1. **Header field `+0x0c` ("width" = `104` for most sprites).** Likely
   a screen-tile size or display-rect width (sentinels `0` =
   compound atlas, `0xFFFFFFFF` = fit-to-source).
2. ~~**Palette inheritance.**~~ **Resolved.** 41/130 sprites carry
   no inline palette and inherit from the most-recently-loaded
   inline-palette sibling at runtime. Confirmed by the load-order
   grouping in the master pack (3 inline heads cover all 41
   followers: 65715 → 65716..65747 (33 sprites), 65753 → 65754,
   65830 → 65831..65838) and by the visual plausibility of the
   reconstructed renders (cohesive Bulánek character / decoration
   palettes). The unpacker now carries a 1024-byte ambient palette
   buffer across `save_resource` calls and stamps every inheriting
   sprite's atlas sidecar with `inheritedFrom: <head_id>`.
3. **Inner opcodes `0x08 / 0x0A / 0x0B / 0x0C / 0x0F`.** All are
   implemented and dispatched, but `0x08` does not appear in the
   master pack; `0x0A..0x0C` appear sparingly. Future sample sets
   may exercise them differently.
4. **Destination-side chroma keying** for the 88 implicit-opaque
   sprites. The destination back-buffer is presumably allocated with
   a DDraw chroma key somewhere in the scene setup; that path is
   upstream of `CDSFlxFile` and hasn't been pinned to a specific
   call site.
5. **`CDSFlxFile::CreateBoundClone`.** Allocates 0x60 bytes via
   `CDSObject::FUN_00425620` and stores `outer+0x48` into the
   satellite's `+0x14`. Looks like a per-instance playhead; needs a
   caller sweep to confirm.

## 10. Reproducing the empirical survey

Helper scripts under `tools/bulanci_unpack/ghidra_analysis/`:

```bash
# Dump the first 11 u32s of every BitmapSprite + per-field histograms.
python ghidra_analysis/inspect_sprite_headers.py unpacked/overlay

# Print one specific sprite's 44-byte header + per-frame inventory.
python ghidra_analysis/dump_chunk_bodies.py 65716

# Verify structural sanity (channels==3, totalSize==size, etc.) and
# show frame/opcode histograms across the whole pack.
python ghidra_analysis/check_sprite_manifest.py unpacked/overlay

# End-to-end regression of the production pixel decoders against all
# 130 master-pack BitmapSprites.
python ghidra_analysis/proto_decoder.py
```

Empirical totals (master pack):

* 130/130 samples — `channels == 3`, `totalSize == .eap-record size`,
  `encodedSize3 == encodedSize`, `flags + 1 == frameCount`.
* 538 keyframe RLE chunks, all decode to `bitmapWidth * bitmapHeight` bytes.
* 1581 delta chunks, all consume their body cleanly.
* 311 palette chunks, all within the 256-entry palette.
* 44 multi-stream variants (`encodedSize != encodedSize2`).
* 130/130 sprites produce an atlas PNG + JSON sidecar + animated GIF.
